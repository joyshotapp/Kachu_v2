## 6. 本輪缺口補齊結果

前一輪列出的四個優先缺口已在上一批完成；本輪再把 event hub 與 identity governance 往前推兩個高價值操作面：

1. suggestion lifecycle 已補成 `pending -> accepted -> sending -> sent`，並封住 terminal state 的重複決策。
2. connector credential degradation layer 已統一到 Meta / Google / 發送路徑，publish 失敗時會顯式降成 `failed` / `delivery_failed`。
3. webhook event envelope 已收斂到共享 event hub，LINE / Meta 都寫入同一組 `occurred_at`、`received_at`、`idempotency_key` 與外部識別欄位。
4. `/tools/publish-google-post` 已補齊 direct publish 的 connector failure semantics，憑證失效時不再誤標 `published`。
5. `publish_content_bundle()` 的 Meta 發送分支已改走共享 resolver，不再繞過 degradation layer。
6. Meta webhook 的 `occurred_at` 已優先採 provider event timestamp，而非 ingest time。

7. event hub 的 query-based replay 已補上 `missing_engagement` 與 `missing_pending_approval` semantic replay policy，讓 operator 可直接補 Meta 下游缺件，不必手動拼低階條件。
8. profile governance 已補 `resolution-history` 聚合查詢，把 merge audit 與 relink timeline 收斂成單一 resolution history 視角。
9. profile governance 已補 `GET /tenants/{tenant_id}/profiles`，支援 `pending_resolution_only` 與 `include_merged`，可直接列出 inferred / low-confidence 身份候選。

上述修補已補上對應測試，並再次完成全量驗證：`161 passed`。

目前仍值得後續追蹤的，主要是「runtime 深度」而不是「缺主路徑功能」：

1. recover sleeping 與 proactive suggestion 仍是輕量 suggestion workflow，不是完整 campaign / journey runtime。
2. event hub 已補 admin 查詢、單筆 detail、LINE / Meta replay、event-id batch replay、query-based batch replay 與補洞型 replay policy；仍缺更完整的訂閱 API 與更進階的 reprocess policy。
3. identity governance 已補 profile detail、manual relink、resolution history 與 profiles queue；仍缺更成熟的衝突處理與人工覆核工作流。
4. AgentOS approval 鏡像同步目前仍採 scheduler polling，而不是 webhook push。

## 7. 後續建議執行順序

1. 把目前的 suggestion workflow 再往前推成真正的 campaign / journey runtime，補 campaign entity、execution log 與 delay/retry policy。
