# Kachu+ 商家導入 SOP（BD/CS 版）
## 從簽約到商家第一次順利用 LINE 開始使用

版本：v1.0  
更新日期：2026-05-09  
適用對象：BD、CS、導入陪跑人員

---

## 這份文件在做什麼

這份文件只保留 BD/CS 真正需要知道的內容：
- 要向商家蒐集哪些資訊
- 要怎麼對商家的導入流程說明
- 商家加入 LINE 後會發生什麼
- 怎麼判斷商家是否成功上手
- 哪些情況要交工程師處理

若你需要實際開 tenant、設 webhook、查 DB，改看 [工程版 SOP](./SOP_商家導入與開通流程_工程版.md)。

若你現在要整理商家與工程交接資料，請直接使用 [商家開通填值工作表](./商家開通填值工作表.md)。

## 階段一：簽約後先向商家確認的資訊

請先蒐集以下資訊並填入商家導入表單：

| 欄位 | 說明 | 範例 |
|---|---|---|
| 店名 | 商家顯示名稱 | 阿財滷味 |
| 行業類型 | 中文描述即可 | 滷味小吃 |
| 地址 | 實體地址或「網路」 | 台北市大安區復興南路一段 |
| LINE OA 帳號 | 商家的 LINE 官方帳號 | @xxxxxxxx |
| owner LINE user_id | 老闆本人 LINE user_id | U1a2b3c4d5e6... |
| Google Business 是否要串接 | 是 / 否 | 是 |
| Meta 是否要串接 | 是 / 否 | 否 |

若商家同意串接外部平台，請再補收以下資訊並交給工程：

| 類別 | 欄位 | 誰提供 |
|---|---|---|
| LINE | line_channel_id / line_channel_secret / line_channel_access_token | 商家或合作夥伴提供 LINE Developers 權限 |
| Google Business | account_id / location_id / access_token / refresh_token | 工程或串接負責人 |
| Meta | access_token / fb_page_id / ig_user_id | 工程或串接負責人 |

補充：
- `line_channel_id`、`line_channel_secret`、`line_channel_access_token` 由工程師使用，不需向商家解釋技術細節，但要提醒商家準備好 LINE Developers 後台權限。
- 若 BD/CS 不確定某個值從哪裡來，直接把收集進度填進 [商家開通填值工作表](./商家開通填值工作表.md)，交工程接手即可。

## 階段二：對商家的導入說明

你可以這樣說：

> 我們會先幫你完成系統開通。完成後，你只要加入 Kachu+ 的 LINE 官方帳號，就可以直接在 LINE 裡跟 AI 助理對話，不需要另外登入後台。

> 加入好友後，系統會馬上主動打招呼，帶你完成一小段 onboarding，大約 5 到 15 分鐘。

> 完成後你平常只要用 LINE 跟 Kachu+ 說話就好，例如查沉睡顧客、請它幫你準備貼文或評論回覆草稿。

## 階段三：工程開通完成後，你要做什麼

當工程師回報 tenant 已建立、webhook 已驗證後，請做以下動作：

1. 通知商家加入指定的 LINE OA。
2. 提醒商家加入後會立刻收到 onboarding 歡迎訊息。
3. 建議商家當下就直接完成 onboarding，不要拖太久。
4. 若商家當天沒空，也可以之後再回來，系統會記住進度。

## 階段四：商家實際會經歷什麼

### 1. 加入好友後

- Kachu+ 會主動推送歡迎訊息。
- 商家不需要先自己打「你好」才開始。

### 2. Onboarding 內容

系統會依序詢問：
- 店名
- 行業類型
- 客人大概多久回來一次
- 地址
- 品牌資料或文件
- 三個簡短的經營訪談問題

預估時間：5 到 15 分鐘。

### 3. 中途停下來怎麼辦

- 不需要重來。
- 商家下次再傳訊息，會從上次停下的地方繼續。

## 階段五：教商家怎麼用

### 商家可以直接說的話

| 商家說法 | 系統反應 |
|---|---|
| 「哪些客人超過 60 天沒來」 | 直接回覆沉睡顧客清單 |
| 「幫我回覆評論」 | 先回處理中，再推回覆草稿給商家確認 |
| 「看一下最近有沒有評論要回」 | 與上面相同，會進評論處理流程 |
| 「幫我寫一篇貼文」 | 先回處理中，再推貼文草稿給商家確認 |
| 「幫我想一篇貼文」 | 直接給建議，不會送審 |
| 「幫我建一個 VIP 顧客標籤」 | 直接建立標籤並回覆結果 |
| 「什麼是好的行銷策略？」 | 直接給諮詢建議 |

### 你要特別提醒商家的差異

- 「幫我寫一篇貼文」：系統會真的幫他起草，之後還會請他確認。
- 「幫我想一篇貼文」：系統只會先給靈感和建議，不會直接進審批。

## 階段六：交接驗收

請陪商家至少做完以下幾件事：

| 驗收項目 | 預期結果 |
|---|---|
| 完成 onboarding | 商家知道對話怎麼開始 |
| 試問「哪些客人超過 60 天沒來」 | AI 能回應 |
| 試問「幫我寫一篇貼文」 | 先收到處理中，再收到草稿 |
| 試問「幫我想一篇貼文」 | 直接收到建議 |
| 商家理解草稿需要確認 | 知道按鈕用途 |

## 常見異常與處理方式

### 情況 1：商家加入好友後沒收到歡迎訊息

先做：
- 請商家確認是否真的加入了正確的 LINE OA。
- 請商家截圖目前對話畫面。

接著：
- 交給工程師檢查 webhook 與 LINE channel 設定。

### 情況 2：商家說系統都不回

先做：
- 請商家提供具體說了哪一句。
- 確認是否只有單一指令沒反應，還是所有訊息都沒反應。

接著：
- 若所有訊息都沒反應，交工程師排查。
- 若只有某種說法沒命中，可先引導商家改用較直接的說法。

### 情況 3：Google / Meta 串接卡住

- 這不需要 BD/CS 自己排查 token 或 API。
- 直接交工程師處理。

## 對商家的口徑

建議維持以下原則：
- 強調「你以後只要用 LINE 就好」。
- 不主動談 token、webhook、資料庫這些技術詞。
- 若系統需要一點時間產生草稿，就說「它正在幫你整理，等一下會再推回來請你確認」。
